# T4: алгоритмы вместо свободного агента

Первая реализация — независимое мини-демо, а не заявка на готовность ко всем заданиям Track 4. Идея: скрипт определяет тип задачи, проверяет время доступности данных, извлекает числа, строит признаки, рассчитывает прогноз и интервал, затем прикладывает проверяемые цитаты. Нейросеть не выбирает числа и не управляет исполнением.

## Что применяют на практике

| Техника | Где полезна в T4 | Что сделано в демо |
|---|---|---|
| Наивный прогноз, средние/медианы, сезонность, ETS/ARIMA | CPI, результаты аукционов, макропоказатели | Среднее последних 6 аукционов; нулевое изменение доходности; медиана/небольшой возврат к среднему. ETS/ARIMA пока не реализованы |
| Линейная регрессия с регуляризацией | Короткая история, мало признаков, риск переобучения | StandardScaler + Ridge, alpha=30, только доступные прошлые наблюдения |
| Деревья с бустингом | Нелинейные зависимости в табличных признаках | HistGradientBoosting, absolute error, 60 итераций, 7 листьев, фиксированный seed |
| Простое усреднение прогнозов | Разные методы ошибаются по-разному | Равные веса наивного, Ridge и деревьев; веса не подбираются на holdout |
| Калибровка по прошлым ошибкам | Честные интервалы вместо произвольной ширины | Хронологический блок калибровки, эмпирический 90%-й квантиль абсолютной ошибки |
| Последовательная проверка во времени | Любой финансовый прогноз | Для каждого cutoff используются только известные метки; train заканчивается до начала calibration |
| Извлечение с проверкой происхождения | Числа в таблицах и документах | Три детерминированных формата, точные смещения цитат, проверка сущности и даты |

Принцип проверки во времени соответствует [rolling forecasting origin в FPP3](https://otexts.com/fpp3/tscv.html). [Раздел FPP3 об объединении прогнозов](https://otexts.com/fpp3/combinations.html) объясняет, почему простое среднее стоит проверять до сложного подбора весов. Это основания для эксперимента, а не обещание выигрыша на наших данных.

[Grinsztajn et al., NeurIPS 2022](https://papers.nips.cc/paper_files/paper/2022/hash/0378c7692da36807bdec87ab043cdadc-Abstract.html) исследуют силу деревьев на типичных табличных данных. Из этого не следует, что дерево обязательно предсказывает рынок: оно здесь лишь один кандидат на равных условиях.

[Zaffran et al., ICML 2022](https://proceedings.mlr.press/v162/zaffran22a.html) рассматривают адаптивные conformal-интервалы для временных рядов. В демо реализована более простая калибровка на отложенных прошлых ошибках. Из-за серийной зависимости она **не даёт гарантии покрытия 90%**. Измеряется фактическое покрытие и официальный interval score; адаптивная калибровка — следующий эксперимент, не реализованная возможность.

Применение этих методов к отдельным семействам T4 — наш инженерный выбор. Для EPS понадобятся нормализация кварталов/единиц и consensus surprise; для CPI — сезонность и реальные исторические публикации; для COT — нормировка позиций на open interest и реальные даты публикации; для ставок — форма кривой и сценарии политики. Это пока план расширения, а не описание проверенных компонентов.

## Граница нейросети

В текущих прогонах **0 вызовов нейросети**. `accept_locator_response` реализует только защитную границу будущего поискового помощника: допустимы идентификатор уже отобранного документа и его точная цитата. Чужой документ, изменённое число, будущая дата, лишнее поле с кодом или прогнозом отвергаются.

Клиент House и автоматическое обращение к модели ещё не подключены. Поэтому нельзя утверждать, что проверены скорость, качество или лимиты живого LLM-поиска. Будущий интегратор должен ограничить его двумя вызовами и коротким списком фрагментов; численные решения остаются за алгоритмами. Неизвестный формат сейчас останавливает задачу, а не создаёт догадку.

## Данные и ограничения

Источники: [Treasury daily yield XML](https://home.treasury.gov/treasury-daily-interest-rate-xml-feed) и [TreasuryDirect auction API](https://treasurydirect.gov/legal-information/developers/web-api-security/). Для каждого ответа сохранены URL, UTC-время загрузки и SHA-256. Объём истории v2: 2013–2025; 2025 нужен для разрешения целей конца 2024 года.

Это текущие исторические выгрузки, **не заверенные снимки, существовавшие в прошлом**. Для доходностей вводится задержка доступности 2 календарных дня. Для аукционов доступность результата — не раньше следующего дня и `updatedTimestamp`; известные поздние изменения тем самым не выдаются за старую информацию. Эта мера не заменяет настоящий архив vintage-данных. Признаки объёма/повторного размещения исключены из моделей, поскольку в сгенерированной истории нет проверенной даты объявления каждого такого признака.

SEC companyfacts и CFTC API при проверке вернули HTTP 403. Обход ограничений не выполнялся. EPS, CPI, credit и COT в этот набор не включены. Три задания по доходностям используют одни и те же ряды: это **не три независимых экономических источника**.

## Как устроен замер

До просмотра результатов закреплены `lab/preregister.json`, методы и временное разбиение. В актуальной v2 48 задач 2017–2019 годов используются для выбора одного общего метода. Затем этот выбор фиксируется в `selection.json`; 48 задач 2022–2024 оцениваются один раз. Всего 504 прогнозируемые строки, но статистически независимых наблюдений существенно меньше.

Первый прогон v1 с holdout 2020–2021 сохранён в `test-output/independent-demo`. Аудит после его раскрытия нашёл 33 повторяющихся исторических обучающих примера, у которых следующий результат уже был опубликован на дату начала примера. Будущих признаков относительно этих дат не найдено, но такие примеры не соответствуют постановке будущего прогноза. В v2 они исключены; методы, гиперпараметры и правило выбора не изменены. Чтобы не выдавать повторный просмотр за независимую проверку, v2 получила новый holdout 2022–2024. Это исправление описано в заранее сохранённом плане v2. Старый результат не стёрт и не используется как финальное доказательство качества.

Каждый кандидат обучается заново внутри своей задачи, только на её прошлом. Между train и calibration исключены обучающие примеры, чей результат стал известен слишком поздно. Калибровочная выборка не используется для обучения Ridge/деревьев. Она определяет только ширину интервала.

Каждый контейнер видит один каталог `/input` и свой `/output`, работает без сети, без root, с read-only корнем, 2 CPU и 2 GiB RAM. Правильные ответы, исходные выгрузки и другие задачи туда не монтируются. Результаты видит отдельный контейнер оценщика.

Импортируются формулы официального оценщика **5.2.2**, commit `1c744e1d6725340643a533f436517d72b53ca0e1`, shared toolkit **2.5.1**. Проверяются JSON schema, полный набор сущностей, конечность чисел, точные цитаты, принадлежность источника сущности и cutoff. Официальная проверка claims применяется только к дословным цитатам; неожиданный вызов NLI вызывает ошибку. Полный production verifier и его NLI-ансамбль не запускались, результат помечен `rankable=false`.

Сначала считается среднее внутри семейства, затем среднее четырёх семейств. Доверительный интервал разницы с наивным прогнозом считается парным bootstrap по двенадцати квартальным блокам holdout. Он приблизительный: блоков мало и остаточная временная зависимость возможна.

Старый V1 сравнивается по его исходным прогнозам/интервалам с общей проверенной оболочкой цитат. Поэтому строка `legacy_v1` не является его исходным end-to-end результатом. Старые leaderboard-числа 0.1388/0.1023/0.1129 нельзя напрямую сравнивать с этим демо: изменились задачи и версия метрики.

Условие отправки сохранено буквально: **score > 2**. Область текущей сырой метрики — [0,1], так что это условие невыполнимо. Шкала не переименовывается и не умножается ради прохождения порога. Дополнительно закрывают отправку отсутствие полного покрытия, настоящих vintage-данных и полного официального verifier. Никаких посылок этот стенд не делает.
